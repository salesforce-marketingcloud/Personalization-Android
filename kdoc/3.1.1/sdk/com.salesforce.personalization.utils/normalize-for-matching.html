sdk/com.salesforce.personalization.utils/normalizeForMatching

normalizeForMatching

@RestrictTo(value = [RestrictTo.Scope.LIBRARY_GROUP])
fun String.normalizeForMatching(): String

Canonical form of a string for case- and whitespace-insensitive equality. Trims surrounding whitespace, then lowercases with Locale.ROOT (locale-independent). Not limited to any one kind of value — its prevalent use today is normalizing engagement action names and content-zone / component names, where it is the single source of truth so distinct comparisons of the "same" string cannot drift: both the EngagementLimiter dedup key (lowcodemobile) and EngagementPayloads' action lookup (sdk) normalize through here, so the "already tracked" equivalence and the "which payload" equivalence agree — a case that resolves to one payload also dedups as one.

ASCII only. These names (content-zone names, component names, engagement action names) must match the backend server-app-config, which restricts them to ASCII. Non-ASCII input is not supported: a developer who passes a Unicode name will not match any configured name regardless of how it is normalized here. Because the domain is ASCII, a simple trim + Locale.ROOT lowercase is sufficient and produces the same equivalence on both platforms (iOS sfpNormalize uses trimmingCharacters(...).lowercased()); there is no need for Unicode case folding or NFC normalization. Locale.ROOT (not the default locale) avoids the Turkish dotless-ı hazard for any stray non-ASCII that slips through, so "VIEW"/"view" always agree.

The order is trim → lowercase, and it must match iOS exactly.
